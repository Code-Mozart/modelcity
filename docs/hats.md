| ^6 | decision | decided | **Through-node curve model:** nodes lie *on* the curve and each carries a heading. An edge between two nodes is one of: *bend* (straight, arc, straight; the arc's circle is tangent to both heading lines), *S-curve* (straight, arc, straight through the inflection point, arc, straight; both arcs share one radius), *hook* (same-direction two-arc edge, up to ~285 degrees; provisional, not designed). A single arc cannot exceed 180 degrees in the bend form. Source: handover section 2. See ^7, ^8. |
| ^7 | decision | decided | **Shape tag:** positions + headings + radius do not fully determine an edge (same data can be a bend or an S; a hook has a rotation direction). So each edge stores a shape tag (bend / S / hook, plus first turn direction). It is chosen automatically at creation and cleared when a heading is edited. If a stored tag stops being valid the edge falls back to automatic choice. Refines ^6. |
| ^8 | decision | decided | **Radius:** one per edge, either *auto* (the largest that fits) or explicit. Changing the radius never changes headings. Bend gesture: the circle tangent to both heading lines through the cursor, grabbed at the arc midpoint. S/hook gesture: drag along the radial direction; both arcs of an S share the radius. Double-click resets to auto. Minimum radius 0.5 m in the demo (defaults per road class: see handover, unverified). Refines ^6. |
| ^9 | decision | decided | **Handle vocabulary:** black dot = node (position); black arrow with ring = heading (arrow tip drags it); blue point = where the two heading lines meet (bend), dragging sets both headings; on an S it is the generated inflection point; orange ring = radius; turquoise = corners of the control polygon (S: display only; hook: drag sets radius). Overlay colors: purple curve, blue guides, red labels. The handover's wider color legend (gray committed, green creating, magenta modifying, blue selection, red invalid) is not yet applied. Handles keep a constant on-screen size at any zoom. See ^6, ^8. |
| ^10 | decision | decided | **Insert a node on a curve:** the new node takes the tangent as its heading and both halves keep the radius and a matching shape tag, so the curve does not change. See ^6, ^7, ^8. |
| ^11 | decision | decided; the tools (M, A, I keys) were superseded by ^44 | **Editing conventions (demo):** tools Move / Append / Insert (keys M, A, I); Append extends at the nearer end of the path, new heading chosen so the new edge is a single bend; right-click or Del removes a node; Esc returns to Move; Shift while dragging a heading snaps to 15 degrees; handles win over empty space, nodes win over other handles when the cursor is right on them. | ^30 | decision | decided | **Camera and pointer controls (supersedes ^14, answers ^28).** Mouse: LMB drag = selection box (later; nothing yet on empty space); RMB drag = pan; MMB drag = rotate and precise zoom about the point where the drag started: horizontal movement rotates (right = clockwise), vertical movement zooms (up = zoom in), like Blender's Ctrl+MMB (revised by the user after testing; originally vertical movement changed the rotation sensitivity). Wheel = zoom at the cursor. While rotating: Esc cancels the rotation (restores the view from before the drag); N, E, S, W set the rotation so that north/east/south/west points up (N = reset); the cursor turns into a compass (needle points to world north) with N, E, S, W key chips, which can also be clicked (LMB while MMB is held); layout in ^33. The grid is pinned to the camera: it stays axis-aligned to the screen and does not move at all while rotating (it has its own center in the view, separate from the camera center, which moves when rotating about an off-center pivot); it only follows panning and zooming (revised after testing). |
| ^31 | decision | assumed | **Details I filled in for ^30:** (a) rotation is 0.4 degrees per horizontal pixel; (b) zoom is exponential, 1% per vertical pixel from the start of the drag (scale = scale at start x e^(0.01 x pixels moved up)), so returning to the starting height returns to the starting zoom; (f) a per-axis dead zone of 20 pixels around the drag start (8 at first, raised by the user after testing): horizontal movement within it does not rotate and vertical movement within it does not zoom, so a mostly vertical drag does not also rotate a little and vice versa; outside it the effect starts from zero (no jump), and after an N/E/S/W jump the dead zone is re-centered on the pointer. This recreates Blender's "Dolly" zoom style, where the zoom factor is 1 + (distance moved) x 0.01 per pixel, dragging up zooms in; the exact current Blender source could not be read (projects.blender.org is not reachable from this session), the exponential form matches it to first order and never degenerates; (c) a right click without movement still removes a node (kept from ^11), a right drag never does; (d) the compass only exists during the middle-button drag, there is no permanent rotation indicator yet; (e) the world rotation is stored in the view as `rot` radians, positive = clockwise on screen. |
